# 04 — Field App keeps the lens sets it loaded at startup until the app is reloaded

**Status:** ready-for-agent
**Category:** bug
**Blocked by:** None — can start immediately

> *This was generated by AI during triage.*

Reported 2026-10-01: a lens set was assigned to a retail point in the Admin Portal; the Field App,
already open at that retail point, said no lens sets were assigned. A browser refresh fixed it.
Confirmed in code: `ReferenceDataClient.EnsureLoadedAsync` returns at once after the first
successful load of the session, and the only caller of `RefreshAsync` is the form's Retry button
after a failed load. Nothing reloads on sign-in or on switching location either — and lens sets
are scoped to the current location, so a technician who switches retail point keeps the previous
one's lens sets (the server then refuses a record that uses one).

## Agent Brief

**Category:** bug
**Summary:** The Field App's reference data and lens sets follow the current location and are
refreshed when a technician starts a record.

**Desired behavior:**
- Signing in, signing out and switching current location each discard the in-memory copy, so the
  next read loads for the new user and location. Sign-out must not leave the previous user's copy
  readable in memory.
- Opening a consultation form or Leads while online fetches fresh data; if the fetch fails
  (offline, 5xx, expired token) the copy already held — in memory, else the IndexedDB cache — is
  used exactly as today. A form must never wait indefinitely on the network: offline opens as
  fast as it does now.
- Data is not swapped under a form that is already open and part-filled.
- The IndexedDB cache's lens sets belong to one location: a copy written at one retail point is
  not presented as another's after an offline switch. (Reference items and exclusions are global
  and may be reused; lens sets may not.) If that changes what the cached shape means, bump the
  cache's shape marker the way the existing code does.

**Key interfaces:**
- `IReferenceDataClient` / `ReferenceDataClient` — load, refresh, cache.
- `AuthTokenStore.Changed` — already fires on token and location changes.

**Acceptance criteria:**
- [ ] Assign a lens set in the Admin Portal, then open a new test in an already-open Field App
      (online): the lens set is offered without a reload.
- [ ] Switch location: the lens range list is the new location's.
- [ ] Offline, a form opens from the cached copy as before.
- [ ] Offline after a location switch, the previous location's lens sets are not offered.
- [ ] A part-filled form's options don't change while it is open.

**Out of scope:**
- Push or live updates while a form is open.
- Server-side lens-set availability rules.
