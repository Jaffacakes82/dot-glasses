# 03 — Access audit: what can a user with no assignment, or no retail point, reach?

**Status:** ready-for-agent
**Category:** bug
**Blocked by:** None — can start immediately (independent of 02)

> *This was generated by AI during triage.*

Reported 2026-10-01 alongside ticket 02: a thorough permissions check is wanted across the
application. A user is meant to always keep at least one assignment, but one can exist with none
(for example after a database clear-down), and a user assigned only above Retail Point has no
recording location.

## Agent Brief

**Category:** bug
**Summary:** Prove, with tests, what three kinds of user can reach across the API and the Admin
Portal, and fix anything that leaks.

**Users to check:** (a) no assignments at all; (b) assigned only above Retail Point, using the
Field App API; (c) a Retail Point `User` with a valid location, on the Admin Portal.

**Desired behavior:**
- (a) sees no hierarchy-scoped rows anywhere, passes no level-gated policy, and cannot record.
  Global libraries (reference data, lens powers) may still be readable; the lens sets reaching
  their location must come back empty.
- (b) can use the Admin Portal at their level, but every create endpoint refuses with the
  `CurrentLocationCheck` reason.
- (c) reaches only the `[Authorize]`-only screens, sees only their own subtree, and is refused
  on every write action and every policy-gated screen.

**Deliverable:**
- Integration tests in the existing Web test project covering every API controller action and
  every Admin Portal controller action for the three users, in the style of the existing access
  policy tests.
- A short findings list appended to this ticket: each endpoint that behaved wrongly, and the fix.
- Fixes for anything found, each keeping data scoping and RBAC separate.

**Acceptance criteria:**
- [ ] Every controller action is covered for user (a); a new action without coverage fails a test.
- [ ] No endpoint returns a hierarchy-scoped row to user (a).
- [ ] No create endpoint accepts a record from (a) or (b).
- [ ] Findings are listed here, including "none found" where that is the result.

**Out of scope:**
- The Field App's client-side route gate — ticket 02.
- Changing the role or level model.
