# 08 — Lens Sets becomes a list, with a page per lens set

**Status:** resolved
**Category:** enhancement
**Blocked by:** None — can start immediately

> *This was generated by AI during triage.*

Feedback after ticket 01 shipped (2026-10-01): the Lens Sets screen is busy and does several jobs
at once — choosing a lens set, editing its lenses, assigning lens sets to organisations, retired
lens sets and creating one all share a page. Decisions below were agreed in a grilling session the
same day. This supersedes ticket 01's "one lens set at a time, chosen from a picker" layout; the
lens table, its chips and the Add lens dialog from that ticket carry over unchanged.

No glossary or ADR change: this is layout only. Permissions are unchanged.

## Agent Brief

**Category:** enhancement
**Summary:** Split the Lens Sets screen into a list of lens sets and a separate page for one lens
set, where its lenses are configured and it is assigned to organisations.

**Current behavior:**
- One page. A "Lens set" picker chooses which set is on screen; below it sit that set's details,
  its lens table, an "Assign lens sets to a retailer" form (pick one organisation, tick several
  lens sets), a block of retired lens sets, and the Create lens set dialog.

**Desired behavior — the list page ("Lens sets" tab):**
- A table with one row per lens set: Name (description beneath it), Owned by, number of lenses,
  number of organisations it is assigned to, Status, and a way to open it.
- The lens count reads "No lenses yet" for an empty set (the Field App does not offer an empty set).
- The assigned count is direct assignments only, not the outlets an assignment reaches.
- Retired lens sets are rows in the same table. A status filter offers Active, Retired and All and
  opens on Active. A retired row shows a Retired status and, for a caller who may edit that set, a
  Reactivate action.
- The name search stays, as a filter on the table, and combines with the status filter.
- Create lens set stays here. A created set opens straight on its own page.
- The "Lens sets" / "Lens powers" tabs appear on this page (and on Lens powers) only.
- The picker and the organisation-first assign form are gone.

**Desired behavior — the lens set page:**
- Its own URL, reached from the list. A breadcrumb back to the list ("Lens Sets › <name>") instead
  of tabs.
- Header: name, description, owning organisation, and — for a caller who may edit it — Edit (name
  and description) and Retire. Retire returns to the list.
- "Lenses in <set>": the existing lens table, Add lens, Edit and Remove, and the existing Add lens
  dialog, behaving exactly as now (including a refused lens reopening the dialog on the admin's
  input).
- "Assigned to": the organisations this set is directly assigned to, each removable where the
  caller may unassign there, and one picker to assign it to another organisation, one at a time.
  The picker lists the same organisations as today (retailers and retail points in the caller's
  scope), leaving out those it is already assigned to. The note that an assignment reaches every
  outlet beneath the chosen organisation stays.
- Every write on the page (lens add/edit/remove, assign, unassign, edit details, reactivate)
  returns to this page.
- A set owned above the caller: lenses shown without Add, Edit or Remove and with the existing
  "owned above your organisation" line; "Assigned to" still usable within the caller's scope.
- A retired set: the whole page is read-only — lenses and assignments shown as they were — with a
  Reactivate action for a caller who may edit it.
- A lens set id that does not exist returns to the list rather than erroring.

**Acceptance criteria:**
- [x] The list shows every active lens set as a row with the columns above; no picker remains.
- [x] Status filter: Active by default; Retired and All work; search combines with it.
- [x] Opening a row lands on that lens set's page; the breadcrumb returns to the list.
- [x] Creating a lens set lands on its page; retiring one lands on the list.
- [x] Assign and unassign work from the lens set's page, one organisation at a time, and an
      already-assigned organisation is not offered again.
- [x] Each write on the lens set's page returns to the same page, including a refused lens.
- [x] A retired lens set's page offers no write except Reactivate; the server refuses the others.
- [x] A set owned above the caller is read-only for lenses and assignable within scope.
- [x] Every action still re-checks its policy server-side; nothing relies on a hidden button.
- [x] No horizontal page scroll at phone width on either page.
- [x] Existing lens set tests are updated to the new pages; the full suite passes.

**Out of scope:**
- Which organisation levels a set may be assigned to (kept as today "for now").
- Assigning several lens sets to one organisation in a single step.
- Any change to the Add lens dialog, the Lens powers page content, or lens set permissions.
