# 05 — A field's error stays on screen after the answer is corrected

**Status:** resolved
**Category:** bug
**Blocked by:** None — can start immediately

> *This was generated by AI during triage.*

Two reports from 2026-10-01 turned out to be this one bug, reproduced locally:

- **Lens choice.** Untick "Same lens for both eyes", choose only the right eye, press Continue as
  Lead (or Save): "Choose a lens for the left eye." appears, correctly. Choose a left lens: the
  message stays under the now-filled dropdown.
- **Reason not purchased.** Save a Lead with no reason: the error appears. Choose a reason: the
  error stays beside the chosen reason. Pressing Save again clears it and the record goes through.

Cause: `FormErrors` is only cleared at the start of the next pre-submit check; changing a control
doesn't clear that control's message. The same happens for every field (name, phone, and so on).

Not reproduced: the right eye being *forced* to the left eye's lens. Unticking starts the right eye
on the lens already chosen (by design), and the right-eye list offers only lenses of the left
lens's type, with a hint saying so; any of those could be picked. If it recurs, note which lens
set and which lenses.

## Agent Brief

**Category:** bug
**Summary:** Changing an answer on a consultation form clears the error shown against it.

**Desired behavior:**
- When a technician changes a control, the message attributed to that control's field key(s)
  disappears immediately. Other fields' messages stay.
- A lens choice clears the lens keys it sets (each eye's sphere, and the lens type); changing lens
  range clears every lens-section key; a dropdown with an "Other" text clears both of its keys.
- The summary line ("Please fix the highlighted fields…") goes once no field error is left.
- Server rejections shown on a Failed record being corrected behave the same way.
- No re-validation on every change: errors are cleared on change and only raised again by the
  next save, which still runs the whole shared check.

**Key interfaces:**
- `FormErrors` — gains a way to clear one field's message.
- The consultation form's controls and `LensRangeSelector` — call it on change.

**Acceptance criteria:**
- [ ] Neither reproduction above leaves a message beside a corrected answer.
- [ ] Correcting one field leaves another field's message in place.
- [ ] Save still shows every failure the shared rules report.

**Out of scope:**
- The wording of the messages — ticket 06.
- Changing which lenses the right eye is offered.
