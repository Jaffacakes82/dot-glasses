# 01 — Lens Sets screen follows the prototype's layout

**Status:** ready-for-agent
**Category:** enhancement
**Blocked by:** None — can start immediately

> *This was generated by AI during triage.*

Feedback from hand-testing on staging, 2026-10-01: the built Lens Sets screen kept the prototype's
Add lens dialog but not its page layout, and reads much worse for it. Three points were raised
(doesn't look like the prototype; lens sets sit side by side; the lens powers lists are hard to
read) and they are one piece of work.

Prototype (primary source): branch `prototype/lens-set-admin-screen`, the single HTML page under
the Admin Portal's Catalogues views, **variant A** ("Configurator dialog") and its "Lens powers" tab.

## Agent Brief

**Category:** enhancement
**Summary:** Lay the Lens Sets screen and the Lens powers page out the way prototype variant A does.

**Current behavior:**
- Every lens set is a card in an auto-fit grid, so two or more sets sit side by side, each with a
  five-column lens table squeezed into a narrow card.
- A lens's coatings and pairings are comma-joined text.
- Lens powers is a separate page showing each value list as a cloud of badges.

**Desired behavior:**
- One lens set is on screen at a time, chosen from a "Lens set" picker at the top, with a line
  beside it naming the owning org, the orgs it is assigned to and the number of lenses.
- Below it, one full-width card: "Lenses in <set>", the Add lens button, and the lens table
  (Label, Lens power, Lens type, Coatings, Pairings, actions).
- Coatings render as chips; pairings as chips reading "A → B"; no pairing shows "—".
- "Lens sets" and "Lens powers" are two tabs of the same screen. Lens powers shows one scrollable,
  single-column list per value (sphere, cylinder, axis, add, pupil distance), each with a one-line
  summary of its range and step, then the rules list. Values still come from `LensPowerValues`
  and are formatted by its formatters; nothing is restated in the view.
- The chosen lens set survives a POST-redirect-GET (add, edit or remove a lens, a refused lens that
  reopens the dialog) — the screen returns to the set that was being worked on.
- Everything the prototype did not cover keeps working and gets a sensible place in the new
  layout: create lens set, edit name/description, retire, the retired list with reactivate,
  assign to an org, unassign, search, and the "owned above your organisation" read-only state.
- No lens sets at all, and a set with no lenses, each have an empty state.

**Key interfaces:**
- `CataloguesIndexViewModel` — needs to carry which lens set is selected.
- `LensPowersViewModel` and its page — becomes the second tab.
- The Add lens dialog and its script are unchanged.

**Acceptance criteria:**
- [ ] With three lens sets, the screen shows one set's lenses at full width and a picker to switch.
- [ ] Coatings and pairings render as chips, pairings as "trigger → paired".
- [ ] Lens powers is a tab; each value list is a single scrollable column with its range summary.
- [ ] After adding, editing or removing a lens, the same lens set is still selected.
- [ ] Create, edit, retire, reactivate, assign, unassign and search all still work, and the
      `PresetCatalogue.*` policy checks are unchanged.
- [ ] Usable at phone width with no horizontal page scroll (the table may scroll inside its card).
- [ ] Existing Web tests for the screen pass, updated only where they asserted the old markup.

**Out of scope:**
- Prototype variants B (grid) and C (CSV import).
- Any change to lens rules, the Add lens dialog's behaviour, or permissions.
- The Field App.
