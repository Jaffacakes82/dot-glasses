# 02 — Field App pages open from a typed URL without sign-in or a current location

**Status:** ready-for-agent
**Category:** bug
**Blocked by:** None — can start immediately

> *This was generated by AI during triage.*

Reported 2026-10-01: signed in as a user with no organisation assigned, typing a Field App URL
loaded the consultation form. Confirmed in code: only Home checks `AuthTokenStore.IsAuthenticated`
and the current location, then redirects to login / no-location / outlet-select. Every other page
renders for anyone. The server still refuses the record (`CurrentLocationCheck`), so nothing is
mis-recorded — but the technician fills in a form that can never save, and it lands on Failed
records.

## Agent Brief

**Category:** bug
**Summary:** Every Field App page applies the same sign-in and current-location gate Home does.

**Current behavior:**
The consultation form, Leads, Settings, Failed records and Messages render when opened directly,
whether or not there is a token or a current location.

**Desired behavior:**
- Not signed in → login, from any page.
- Signed in with no current location → the same destination Home would choose (no-location when
  the user has no eligible retail point, outlet-select otherwise), from any page that records or
  reads location-scoped data: the consultation forms and Leads.
- Settings and Failed records stay reachable without a location (a technician must still be able
  to send or discard queued records, switch location and sign out) but not without sign-in.
- The gate lives in one place, not copied into each page.
- Offline behaviour is unchanged: a technician with a persisted token and location still opens
  forms with no connectivity.

**Key interfaces:**
- `AuthTokenStore` (`IsAuthenticated`, `CurrentLocationId`) — the existing source of truth.
- The router / main layout — the natural single place for the gate.

**Acceptance criteria:**
- [ ] Opening a consultation URL or Leads with no token goes to login.
- [ ] Opening a consultation URL or Leads with a token but no current location goes where Home
      would send that user, and never renders the form.
- [ ] Settings and Failed records open with a token and no location.
- [ ] Login, no-location and outlet-select never redirect to themselves.
- [ ] A signed-in technician with a location, offline, can still open a consultation form.

**Out of scope:**
- Server-side checks (already in place).
- The wider access audit — ticket 03.
