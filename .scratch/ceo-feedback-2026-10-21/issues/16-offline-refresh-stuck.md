Feedback: "Refreshing while offline gets stuck on this screen." The screenshot (installed app,
phone in flight mode) shows a white screen with the DOT logo, a crossed-out cloud and "You're
offline". That is Chrome's own fallback page for an installed web app, shown when the service
worker doesn't answer the page request — the app itself never starts. A technician who has been
online before should be able to open and refresh the app with no connection (CLAUDE.md, Offline
sync).

## Agent Brief

**Category:** bug
**Summary:** The installed Field App opens and refreshes offline, on any page, once it has been
online once.

**Desired behavior:**
- Opening or refreshing the app offline — on the home page or a deep link such as a form or
  `/failed-records` — loads the app from the service worker's cache and shows the app's own
  offline state, never the browser's.
- After a new release is deployed, a device that was online once since still works offline.

**Where to start:** use `/diagnosing-bugs`. Reproduce on staging (`nonprod.app.dotglasses.com`)
with DevTools → Application: is a service worker active, and does Cache Storage hold
`offline-cache-*` with `index.html` and the framework files? Candidates, none confirmed:
- the published worker never finished installing (one failed asset fetch or integrity mismatch
  fails the whole `cache.addAll`, e.g. if Static Web Apps serves a file differently from the
  hashes in `service-worker-assets.js`);
- the navigation fallback in `service-worker.published.js` (`cache.match('index.html')`) misses,
  so it falls through to `fetch` and fails;
- the app is fine to load but the boot path awaits a network call before rendering.

**Key interfaces:**
- `src/DotGlasses.App/wwwroot/service-worker.published.js`, `index.html` (registration),
  `DotGlasses.App.csproj` (`ServiceWorker` item).

**Acceptance criteria:**
- [ ] On staging, installed on Android: go online once, go to flight mode, refresh on the home
      page and on a form — the app loads both times.
- [ ] The cause is named in the PR, with how it was confirmed.
