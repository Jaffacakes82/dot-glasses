## Agent Brief

**Category:** enhancement
**Summary:** Every required choice on the Field App's forms starts blank and must be answered.

**Desired behavior:**
- Gender and Outcome start on a "Select…" placeholder. Audit the rest of the three forms (and
  the Admin Portal's lead conversion form) for any other required control with a preselected
  answer and treat it the same way. Optional controls ("—"), and checkboxes whose unticked state
  is a real answer, stay as they are.
- Leaving one blank shows a pre-submit error on that control, in the existing voice ("Choose a
  gender.", "Choose an outcome."), keyed on the request property name so `FormErrors` puts it on
  the right control.
- With Outcome blank, the "Needs glasses" sections stay hidden (as for "No glasses needed").
- Seeding is unchanged: a Lead continued from a Test, or a Sale converted from a Lead, still
  starts with the carried answers.
- The unsaved-data check (`HasUnsavedData`) counts a chosen Gender or Outcome as entered data.

**Key interfaces:**
- `ConsultationForm.razor` — the client fields become nullable; the request DTOs don't change
  (the server already refuses an out-of-enum value).
- `ConsultationRules` — add a message only if the server needs one; any new message follows the
  guard test in `ConsultationRulesTests` (no property or enum names).

**Acceptance criteria:**
- [ ] A new Test, Lead and Sale open with Gender blank; a new Test opens with Outcome blank.
- [ ] Saving with either blank shows the error on that control and queues nothing.
- [ ] Converted/continued records still start with the carried values.
