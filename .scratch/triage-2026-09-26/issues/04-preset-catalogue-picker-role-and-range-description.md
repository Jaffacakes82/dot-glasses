## What these fields actually do (traced)

**Field App picker role** (`PresetCatalogue.Kind`: `Other` / `SixLensSet` / `NineLensSet`).
- The Field App's lens-range dropdown is hard-coded to three choices: **6-Lens Set**, **9-Lens
  Set** and **Custom prescription** (`src/DotGlasses.App/Pages/LensRangeSelector.razor:14-16`).
  To fill the 6-Lens and 9-Lens choices, it picks the catalogue whose `Kind` is `SixLensSet` or
  `NineLensSet` from the catalogues assigned to the technician's retail point (lines 213-214).
- It replaced an older rule that matched on catalogue *name* containing "6-Lens"/"9-Lens".
- **At most one catalogue in the whole system** may hold `SixLensSet`, and one `NineLensSet`. The
  check is global, not per country or retailer (`PresetCatalogueAdminService.HasCatalogueWithKindAsync`,
  `CreateCatalogueRequestValidator`/`UpdateCatalogueRequestValidator`). The two seeded catalogues
  already hold both, which is why "it does not let you add new entries for that role". Any new
  catalogue can only be `Other`.
- **An `Other` catalogue never appears in the Field App at all.** Nothing on the device reads it.
  Creating one, filling its lens roster and assigning it to a retailer currently has no effect on
  the device.

**Diopter / strength range** (`PresetCatalogue.RangeDescription`, free text ≤ 100).
- Display-only. It appears as "Diopter range: …" on the Admin Portal catalogue card, and nowhere
  else: it is not on `PresetCatalogueDto`, so the Field App never sees it. It isn't derived from
  or checked against the catalogue's actual lens roster, so it can disagree with it.

**Net effect:** the screen invites admins to build catalogues that do nothing, and it labels an
admin note as if it were a setting.

## Needs info — product decisions

1. **Should different countries or retailers be able to have their own 6-Lens / 9-Lens set?**
   Today there is exactly one 6-Lens set and one 9-Lens set worldwide. Assignment only controls
   *whether* a retail point gets them, not *which* one.
   - (a) **One global set of each is correct.** Then `Other` has no purpose. Stop offering
     "Create package" for anything but the two fixed kinds, or keep it and label `Other` as
     "Not shown in Field App (draft)".
   - (b) **Per-country sets.** Change the uniqueness rule from "one per system" to "one per kind
     among the catalogues assigned to any given retail point". This is a bigger change: the rule
     moves to assignment time, and there is an ambiguity case to design when a retail point
     inherits two.
   - (c) **The Field App should offer any number of named presets**, not just 6/9/Custom. This is
     the biggest change: `LensRangeType` on the wire and in `ConsultationRules`, the Field App
     picker, and reporting all assume exactly two presets.
2. **Is "Diopter range" wanted at all?** Options: keep it as an admin note and relabel it
   "Range note (admin only, not shown on device)", derive it automatically from the roster's min
   and max strength, or drop it.
