# 08 — Retire and reactivate lens sets

## Agent Brief

**Category:** enhancement

**Summary:** Admins can retire a lens set that is no longer sold, and reactivate it later. A
retired set disappears from the Field App and from the assign form. It stays readable on the
historical Tests/Leads/Sales that name it.

**Current behavior:**
`PresetCatalogue` is `ISoftDeletable`, but nothing ever retires one.
`CataloguesController` / `PresetCatalogueAdminService` can create, update, add or remove a lens
option, assign or unassign, and save coating availability. They have no retire action. Records
reference a lens set by `PresetCatalogueId`, so a set can't be hard-deleted.

**Desired behavior:**
- **Retire** and **Reactivate** actions on the Catalogues screen, following the Organisations
  screen's deactivate/reactivate pattern:
  - Soft-delete via `Remove()` and `AuditSaveChangesInterceptor`.
  - Reactivation clears the soft-delete fields by hand and needs `IgnoreQueryFilters()` at
    *every* point in the chain (CLAUDE.md, Common pitfalls).
  - Retired sets are listed separately, so they can be found again.
- A retired set is excluded from `ListAvailableForCallerAsync`, so the Field App stops offering it
  on its next reference-data refresh. It is also excluded from the assign form's lens-set list.
- Its **assignments are kept** while retired, so reactivating restores it exactly as it was.
- Historical records still resolve the retired set's name and lens power labels (Event History,
  Lead→Sale conversion, and anywhere else that resolves them through
  `ReferenceDataSnapshotProvider`). Check how the provider loads catalogues. It loads retired
  *reference items* deliberately (CLAUDE.md, the Rules bullet), and lens sets need the same.
- A retired set's name is free for reuse. Ticket 10's uniqueness rule is "among active lens sets".
- Who may retire or reactivate: the same rule as editing (ticket 10): admins at or above the
  set's owning org. If 10 hasn't landed, gate it on `PresetCatalogue.Manage` like the rest of the
  screen, and leave a pointer for 10.

**Acceptance criteria:**
- [ ] Retiring a set removes it from `ListAvailableForCallerAsync` for a caller it was assigned
      to. Reactivating restores it, with its assignments intact. Infrastructure test, real
      Postgres.
- [ ] A Sale recorded against a set that is later retired still shows the set's name and lens
      labels in Event History.
- [ ] Retired sets appear in a separate list on the Catalogues screen with a Reactivate action,
      and aren't offered in the assign form.
- [ ] `docs/functional-capabilities.md` §4.6 documents retire/reactivate.

**Out of scope:** hard deletion; editing a retired set's contents.
