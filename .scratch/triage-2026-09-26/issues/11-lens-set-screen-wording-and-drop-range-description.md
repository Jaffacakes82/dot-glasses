## Agent Brief

**Category:** enhancement

**Summary:** The Admin Portal's Catalogues screen calls lens sets "packages" and has a free-text
"Diopter / strength range" field that no business rule reads and the device never sees. Rename
the screen's language to **lens set**, and remove the range field entirely.

**Current behavior:**
- `Views/Catalogues/Index.cshtml` says "Create package", "Package name", "Save package" and
  "Assign packages to a retailer". The card shows "Diopter range: …". The create and edit modals
  both carry a "Diopter / strength range" input bound to `RangeDescription`.
- `PresetCatalogue.RangeDescription` (Domain) is display-only (its own doc comment says so). It
  flows through the admin DTOs, the create/update requests and the validators.

**Desired behavior:**
- **User-facing copy** uses "lens set" throughout the screen: "Create lens set", "Lens set name",
  "Save lens set", "Assign lens sets to a retailer", and so on. This includes the sidebar entry
  and the page title. Code type names stay as they are (`PresetCatalogue`); only product language
  changes, per `CONTEXT.md`.
- **"Diopter / strength range" is removed:** the card line, both modal inputs, the request and DTO
  properties, validator rules, and the `RangeDescription` column, via a migration.

**Acceptance criteria:**
- [ ] No user-facing "package" or "Diopter range" text remains in `src/DotGlasses.Web/Views`. Grep
      is clean, apart from code identifiers.
- [ ] `RangeDescription` no longer exists in `src/` (outside historical migrations), and a
      migration drops the column.
- [ ] The existing Catalogues web tests pass with the renamed copy.
- [ ] `docs/functional-capabilities.md` §4.6 uses "lens set" and no longer lists the range field.

**Out of scope:** renaming code types or routes (`/Catalogues`); anything in 07–10.
