# 01 — Online/offline status never updates after the page first loads

Status: done (implemented 2026-09-09, PR: fix/offline-status-and-dashboard-scoping-2026-09-09)
Blocked by: None — can start immediately
Category: bug

Source: Field App testing, 2026-09-09, Joe — "When offline, app still shows as online - how often
does it check the status?"

## Agent Brief

**Category:** bug (missing event wiring)

**Summary:** The honest answer to "how often" is: **never, after the page first renders.** Two
separate gaps combine to produce this:

1. `idbInterop.js`'s `registerConnectivityCallback` (`src/DotGlasses.App/wwwroot/js/idbInterop.js:182-184`)
   only registers a `window.addEventListener('online', ...)` — there is no `'offline'` listener at
   all, so the app is never proactively told when connectivity drops.
2. `Home.razor` reads `navigator.onLine` via `dotGlassesIdb.isOnline()` exactly once, inside
   `RefreshAsync()` (`Home.razor:101-106`), which only runs from `OnInitializedAsync()` (page load)
   and `SyncNowAsync()` (the manual sync button click). Nothing re-checks or re-renders `_isOnline`
   on any timer or event. `ConnectivitySyncTrigger`'s existing 30-second `PeriodicTimer`
   (`src/DotGlasses.App/Sync/ConnectivitySyncTrigger.cs:31-39`) already polls on an interval, but
   only to drive sync attempts — it never touches `_isOnline` or notifies the UI.

**Desired behavior:** The Home screen's online/offline banner reflects reality within a few
seconds of an actual connectivity change, both directions (going offline promptly shows Offline;
reconnecting promptly shows Online), without requiring navigation or a manual action.

**Key interfaces:**
- `src/DotGlasses.App/wwwroot/js/idbInterop.js:182-188` (`registerConnectivityCallback`/`isOnline`)
  — add a mirrored `window.addEventListener('offline', ...)` calling a new JSInvokable method,
  alongside the existing `online` one.
- `src/DotGlasses.App/Sync/ConnectivitySyncTrigger.cs` — the natural home for the new `OnOffline`
  JSInvokable (mirrors `OnOnline`) and for exposing connectivity *state* (not just sync-trigger
  events) to subscribers, e.g. a `bool IsOnline` property plus a plain C# event
  (`event Action? StatusChanged`) raised from `OnOnline`, a new `OnOffline`, and the existing
  30-second poll tick — this turns the existing "belt-and-braces poll" into the periodic re-check
  the UI is currently missing, not just a sync trigger.
- `src/DotGlasses.App/Pages/Home.razor:14-27,84-106` — subscribe to `ConnectivitySyncTrigger`'s new
  event in `OnInitializedAsync` (unsubscribe via `IDisposable`), update `_isOnline` and call
  `StateHasChanged()` when it fires, instead of only refreshing inside `RefreshAsync()`.

**Acceptance criteria:**
- [ ] Simulating offline (e.g. DevTools' network throttling, or toggling the OS/browser offline)
      while the Home screen is open updates the banner to Offline within one poll interval or
      immediately via the new `offline` event, whichever fires first.
- [ ] Reconnecting updates the banner back to Online the same way (already partially working via
      the existing `online` listener, but verify it still updates the *display*, not just triggers
      a sync).
- [ ] No change to `SyncPendingAsync`/outbox retry behavior — this ticket is about the *displayed*
      status, not sync logic.

**Out of scope:**
- Any change to sync retry cadence or the outbox pattern itself.
- Surfacing connectivity status anywhere other than Home's existing banner (e.g. a global
  layout-level indicator) — not asked for.
