# 03 — Two buttons bypass the `dg-btn` design system (underline/alignment inconsistency)

the main call to action button, and white/clear as secondary buttons."

## Agent Brief

**Category:** bug (design-system inconsistency)

**Summary:** The Admin Portal already has a consistent button system (`.dg-btn` +
`.dg-btn-primary`/`.dg-btn-ghost`, `src/DotGlasses.Web/wwwroot/css/dot-glasses.css:59-98`) and it's
applied consistently across every screen — a full scan of every button in
`src/DotGlasses.Web/Views/**/*.cshtml` found exactly two exceptions, both small "undo" actions
rendered as raw, unstyled `<button>` elements instead:

- `Views/ReferenceData/Index.cshtml:104` — "Restore" (reactivate a retired reference-data option)
- `Views/Organisations/Index.cshtml:130` — "Reactivate" (reactivate a deactivated org node)

Both use inline `style="border:none; background:none; ...; color:var(--dot-blue); font-size:12px;
text-decoration:underline;"` — plain underlined blue text, not a pill-shaped button — which is
almost certainly what reads as inconsistent underline/alignment against the ~40 other buttons on
these same screens, which are all already `dg-btn dg-btn-primary` (orange CTA) or `dg-btn
dg-btn-ghost` (white/transparent-with-outline secondary — already matches the "white/clear
secondary" ask). See this ticket batch's `spec.md` "Notes" section for what was checked and ruled
out (no other button in the codebase currently skips the `dg-btn` classes, and every full-width
button already pairs `width:100%` with an explicit `justify-content:center`).

**Current behavior:**
The Restore/Reactivate actions render as bare underlined text, with no padding, background, or
pill shape, sitting inline inside a small badge/row — visually distinct from every other button on
the page.

**Desired behavior:**
Both actions use the existing `dg-btn dg-btn-ghost` classes (secondary/white-clear styling, per
the reporter's own ask) so they read as buttons consistent with the rest of the screen. Since both
sit inside a small inline badge/list-row context (not a page-level action bar), a compact variant
is appropriate — reuse the same small-button pattern already used elsewhere for compact contexts
(e.g. `style="padding:4px 12px; font-size:12px;"`, as used by the "Add pairing"/"Add exclusion"
buttons on the same `ReferenceData/Index.cshtml` page) rather than the full default `dg-btn`
padding, so they still fit inline without breaking the row layout.

**Key interfaces:**
- `src/DotGlasses.Web/Views/ReferenceData/Index.cshtml:100-106` (Restore button, inside the
  Retired-options `<details>` block)
- `src/DotGlasses.Web/Views/Organisations/Index.cshtml:126-132` (Reactivate button, inside the
  deactivated-node view)
- `src/DotGlasses.Web/wwwroot/css/dot-glasses.css:59-98` (`.dg-btn`/`.dg-btn-primary`/`.dg-btn-ghost`
  — the system to bring both into)

**Acceptance criteria:**
- [ ] Both Restore and Reactivate render as `dg-btn dg-btn-ghost` (or an equally compact
      `dg-btn`-based variant), not raw underlined text.
- [ ] Both remain usable inline within their existing badge/row layout — no visual overflow or
      row-height regression on the Reference Data and Organisations screens.
- [ ] No other button on either screen is changed unintentionally.

**Out of scope:**
- A full re-audit of every button in the app beyond these two — the scan already done for this
  ticket found no other offenders (see `spec.md`'s Notes section); if implementation turns up a
  genuinely new inconsistency, treat it as new information rather than silently expanding this
  ticket's scope.
- Introducing `.dg-btn-secondary` (solid black/white) anywhere — it exists in the CSS but is
  currently unused, and the reporter's "white/clear" ask maps to the already-standard
  `.dg-btn-ghost`, not this class.
