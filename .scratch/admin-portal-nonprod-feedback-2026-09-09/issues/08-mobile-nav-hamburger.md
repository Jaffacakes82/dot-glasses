# 08 — Sidebar nav should collapse into a hamburger menu on small screens, not horizontal scroll

Status: done (implemented 2026-09-09, PR: fix/admin-portal-ux-feedback-2026-09-09)
Blocked by: None — can start immediately
Category: enhancement

Source: Admin Portal non-prod testing, 2026-09-09, Joe — "On smaller screen widths, the nav should
collapse into a horizontal nav at the top of the page with an expandable hamburger menu. At the
moment, a horizontal scroll appears to see all nav options."

## Agent Brief

**Category:** enhancement (responsive layout)

**Summary:** Below 991px, the sidebar already switches from a vertical column to a horizontal bar
at the top of the page — but instead of collapsing the nav links behind a hamburger toggle, it
just lays every link out in a row and lets the row overflow with `overflow-x: auto`, forcing a
horizontal scroll to reach the later items.

**Current behavior:**
`src/DotGlasses.Web/wwwroot/css/dot-glasses.css:311-345`:
```css
@media (max-width: 991px) {
    .dg-shell { flex-direction: column; }
    .dg-sidebar {
        width: 100%;
        flex: none;
        height: auto;
        position: static;
        flex-direction: row;
        align-items: center;
        overflow-x: auto;
    }
    .dg-nav { flex-direction: row; }
    ...
}
```
`.dg-sidebar` (logo + `.dg-nav` links + `.dg-user-chip`) already renders as a horizontal top bar at
this breakpoint — it's the `overflow-x: auto` plus no way to hide/show the link row that produces
the reported horizontal scroll. There's no toggle button, no collapsed state, and no JS wired up
for this today (`_Layout.cshtml:46-105`).

**Desired behavior:**
Below the same breakpoint, the nav links (`.dg-nav`, `Views/Shared/_Layout.cshtml:49-79`) are
hidden by default behind a hamburger button placed in the top bar next to the logo, and expand
(as a dropdown panel or an in-flow list pushing content down — implementer's call) when tapped —
no horizontal scrolling required to reach any nav item. The logo and `.dg-user-chip`
(avatar/sign-out) stay visible in the collapsed top bar; only the nav links themselves are what
collapses.

Bootstrap's own navbar-collapse/hamburger-toggle JS is already loaded
(`bootstrap.bundle.min.js`, `_Layout.cshtml:115`) and is the natural fit here — no new JS
dependency should be needed, just Bootstrap's existing `data-bs-toggle="collapse"` pattern (or its
offcanvas component, also already bundled) applied to `.dg-nav`, restyled with the existing `dg-*`
tokens rather than Bootstrap's default navbar look.

**Key interfaces:**
- `src/DotGlasses.Web/wwwroot/css/dot-glasses.css:215-345` (`.dg-shell`/`.dg-sidebar`/`.dg-nav` and
  their `@media (max-width: 991px)` block — the block to rework)
- `src/DotGlasses.Web/Views/Shared/_Layout.cshtml:46-105` (the sidebar markup — logo, `.dg-nav`
  links, `.dg-user-chip` — needs the hamburger toggle button added here)

**Acceptance criteria:**
- [ ] Below 991px, every nav link is reachable without horizontal scrolling.
- [ ] A hamburger toggle is visible in the top bar below 991px and expands/collapses the nav link
      list.
- [ ] Above 991px, the existing full vertical sidebar (unaffected by this ticket) is unchanged.
- [ ] The logo and user chip (avatar, role, sign-out) remain visible in the collapsed top bar —
      only the nav links collapse.
- [ ] Test at both a tablet width (~768px) and a phone width (~375px) — the "expandable" behavior
      should read comfortably at both, not just the 991px breakpoint edge.

**Out of scope:**
- Any change to the desktop (≥991px) vertical sidebar layout.
- The nav item list itself (which links appear, their order, or the RBAC-based
  `canViewPresetCatalogues`/`canViewCustomOrders`/`canViewReferenceData` visibility already in
  `_Layout.cshtml:24-29`) — only how the existing links are presented at small widths.
