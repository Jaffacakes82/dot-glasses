# 01 — Login page doesn't redirect an already-authenticated user

Status: done (implemented 2026-09-09, PR: fix/admin-portal-ux-feedback-2026-09-09)
Blocked by: None — can start immediately
Category: bug

Source: Admin Portal non-prod testing, 2026-09-09, Joe.

Visiting the login URL while already signed in shows the login form again instead of redirecting
straight to the dashboard.

## Agent Brief

**Category:** bug

**Summary:** `GET /Account/Login` always renders the login form, even for a caller who is already
authenticated.

**Current behavior:**
`AccountController.Login(string? returnUrl)` (`src/DotGlasses.Web/Controllers/AccountController.cs:17-19`)
is `[AllowAnonymous]` and unconditionally returns `View(new LoginViewModel { ReturnUrl = returnUrl })`
with no check of the caller's authentication state.

**Desired behavior:**
If the caller is already signed in, `GET /Account/Login` redirects them straight to the dashboard
(`RedirectToAction("Index", "Home")`) instead of rendering the login form — mirroring what the
`POST` handler already does on a successful sign-in
(`src/DotGlasses.Web/Controllers/AccountController.cs:45-50`). If a `returnUrl` was supplied and is
local (`Url.IsLocalUrl`), redirect there instead, same as the POST handler's own logic.

**Key interfaces:**
- `AccountController.Login(string?)` (GET) — `src/DotGlasses.Web/Controllers/AccountController.cs:17-19`
- `User.Identity.IsAuthenticated` (standard ASP.NET Identity check, already available via `User`
  on the controller) — or `ICurrentUserContext.IsAuthenticated`
  (`DotGlasses.Application.Common`), which `_Layout.cshtml` already injects and uses for the same
  purpose.

**Acceptance criteria:**
- [ ] An already-authenticated user hitting `GET /Account/Login` is redirected, not shown the
      login form.
- [ ] The redirect honors a local `returnUrl` the same way the POST handler does; otherwise it
      goes to `Home/Index`.
- [ ] An anonymous caller still sees the login form as before.

**Out of scope:**
- Any change to the POST login flow, session/cookie handling, or lockout behavior.
