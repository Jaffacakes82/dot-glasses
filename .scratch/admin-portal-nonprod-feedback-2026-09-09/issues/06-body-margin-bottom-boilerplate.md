## Agent Brief

**Category:** bug (leftover scaffold CSS)

**Summary:** `site.css` still carries the default ASP.NET MVC project template's sticky-footer
boilerplate (`html { position:relative; min-height:100%; } body { margin-bottom: 60px; }` — the
classic "reserve space for a fixed footer" pattern), left over from before the app had its own
`.dg-shell` flex layout. This app has no page footer that needs that reserved space, so the 60px
just shows up as a gap under the sidebar/content.

**Current behavior:**
`src/DotGlasses.Web/wwwroot/css/site.css:15-22`:
```css
html {
  position: relative;
  min-height: 100%;
}

body {
  margin-bottom: 60px;
}
```
This is unrelated to and predates the real layout (`.dg-shell`/`.dg-sidebar`/`.dg-content` in
`dot-glasses.css`, rendered from `Views/Shared/_Layout.cshtml:46-105`), which has no footer element
and no need for reserved bottom space.

**Desired behavior:**
Remove the `body { margin-bottom: 60px; }` rule (and the now-pointless `html { position:relative;
min-height:100%; }` pair that only existed to support it) so the sidebar/content run flush to the
bottom of the viewport.

**Key interfaces:**
- `src/DotGlasses.Web/wwwroot/css/site.css:15-22`

**Acceptance criteria:**
- [ ] The 60px gap below the sidebar/content is gone on every screen, authenticated and
      unauthenticated (login, access-denied, etc. — both branches of `_Layout.cshtml:44-113`).
- [ ] No other rule in `site.css` (the `html { font-size }` breakpoint rule, the `.btn:focus`
      outline rule, the `.form-floating` placeholder rules) is touched — only the sticky-footer
      pair.

**Out of scope:**
- Any other cleanup of `site.css`'s remaining scaffold-era rules not related to this reported gap.
