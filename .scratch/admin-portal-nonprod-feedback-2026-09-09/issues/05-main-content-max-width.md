# 05 — Admin Portal main content area capped at max-width:1440px

Source: Admin Portal non-prod testing, 2026-09-09, Joe — "For the main body of the window, can we

## Agent Brief

**Category:** enhancement (layout)

**Summary:** `.dg-content` — the `<main>` element holding every screen's body, next to the fixed
sidebar — has a hard `max-width: 1440px`, so on any viewport wider than that (sidebar width plus
1440px) the content stops growing and leaves unused space to the right.

**Current behavior:**
`src/DotGlasses.Web/wwwroot/css/dot-glasses.css:304-308`:
```css
.dg-content {
    flex: 1;
    padding: 40px 48px;
    max-width: 1440px;
}
```
`.dg-content` sits inside `.dg-shell` (a flex row with `.dg-sidebar`) per
`Views/Shared/_Layout.cshtml:46-105`, so `flex: 1` alone would already let it fill the remaining
width — the `max-width` is what's capping it.

**Desired behavior:**
Remove the `max-width: 1440px` cap so `.dg-content` fills the full remaining viewport width on
wide screens. This is a one-line CSS change on the outer container; it deliberately does not touch
any inner component's own width constraints (tables, cards, forms) — those may still want their
own reasonable max-widths so text/columns don't stretch awkwardly edge-to-edge on very wide
monitors, but that's a per-screen call for whoever implements this, not part of the outer
container's job.

**Key interfaces:**
- `src/DotGlasses.Web/wwwroot/css/dot-glasses.css:304-308` (`.dg-content`)

**Acceptance criteria:**
- [ ] `.dg-content` (and therefore the visible body of every Admin Portal screen) fills the full
      viewport width right up to the sidebar, with no artificial cap, on wide monitors (test at
      e.g. 1920px and 2560px viewport widths).
- [ ] The existing responsive collapse of `.dg-sidebar` below 991px (`dot-glasses.css:311+`) is
      unaffected.
- [ ] No screen's inner content (tables, cards, forms) becomes noticeably harder to read by
      stretching edge-to-edge with no visual grouping — if a screen looks broken at full width,
      it's fine to give that screen's own inner wrapper a sensible max-width rather than
      reintroducing one on `.dg-content` itself.

**Out of scope:**
- Redesigning any individual screen's internal layout/grid.
