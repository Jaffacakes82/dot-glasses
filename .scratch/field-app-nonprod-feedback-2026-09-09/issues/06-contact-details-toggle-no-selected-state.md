# 06 — "Did the customer share contact details?" toggle doesn't show which option is selected

## Agent Brief

**Category:** bug (missing visual state)

**Summary:** The Yes/No toggle in `ConsultationForm.razor:168-171` is bound to `_contactShared`
(a `bool?`) via `@onclick`, but both buttons always render with the exact same classes
(`dg-btn dg-btn-ghost`) regardless of `_contactShared`'s current value — there's no CSS class or
style difference applied when one option is the active selection.

**Current behavior:**
```html
<div style="display:flex; gap:8px;">
    <button type="button" class="dg-btn dg-btn-ghost" style="flex:1;" @onclick="() => _contactShared = false">No</button>
    <button type="button" class="dg-btn dg-btn-ghost" style="flex:1;" @onclick="() => _contactShared = true">Yes</button>
</div>
```
Clicking either button updates state (confirmed by the conditional content below it changing —
`_contactShared == true` shows "Continue as Lead", `== false` shows the test-only note) but
neither button's own appearance changes, so a technician has no visual confirmation of which one
is currently selected.

**Desired behavior:**
The currently-selected button (`_contactShared == true` → Yes, `== false` → No) visually reads as
selected — e.g. swap to `dg-btn-primary` for the active one while the inactive one stays
`dg-btn-ghost`, mirroring how `Settings.razor`'s `.dg-outlet-button.selected` already indicates an
active choice for the location picker (`dot-glasses.css:288-290`). Reuse that same
selected/unselected visual language rather than inventing a new one.

**Key interfaces:**
- `src/DotGlasses.App/Pages/ConsultationForm.razor:168-171`
- `src/DotGlasses.App/wwwroot/css/dot-glasses.css:193-` (`.dg-btn-primary`/`.dg-btn-ghost`) for the
  existing selected/unselected treatment to reuse, and `:288-290`
  (`.dg-outlet-button.selected`) as the precedent for "this is the established pattern for marking
  a choice active" in this codebase.

**Acceptance criteria:**
- [ ] Clicking "Yes" visually marks Yes as selected and No as not selected.
- [ ] Clicking "No" visually marks No as selected and Yes as not selected.
- [ ] The unselected/no-selection-yet initial state (`_contactShared == null`) doesn't show either
      button as selected.
- [ ] No change to the actual save/validation behavior — this is a visual-state-only fix.

**Out of scope:**
- Any other Yes/No-style control elsewhere in the form (`_hardCaseSold`,
  `_orderFromDotGlasses`, `_consentGiven`) — those are real checkboxes with their own native
  checked-state affordance, a different pattern covered (for `_hardCaseSold`'s specific usability
  complaint) by ticket 07 in this same batch.
