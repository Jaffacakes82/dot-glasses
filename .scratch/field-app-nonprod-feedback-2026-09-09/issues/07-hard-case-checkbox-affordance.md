# 07 — "Did this person buy a hard case?" click affordance is unclear

Source: Field App non-prod testing, 2026-09-09, Joe — "'Did this person buy a hard case? (click

## Agent Brief

**Category:** bug (UX / affordance) — not a functional defect, the control already works

**Summary:** `ConsultationForm.razor:239` already renders a real `<input type="checkbox"
@bind="_hardCaseSold">`, wrapped in a `<label>` (so clicking the label text does toggle the
checkbox, per standard HTML label semantics) — but the checkbox is squeezed to the far right of a
`space-between` flex row with `flex:none; width:auto`, and the label text explicitly instructs
"(click for yes)" rather than the checkbox itself reading as the obvious control. This is why it
reads as "clicking a label" rather than "using a checkbox" — the checkbox is present but visually
an afterthought.

**Current behavior:**
```html
<label style="display:flex; align-items:center; justify-content:space-between; gap:8px;">Did this person buy a hard case? (click for yes)<input type="checkbox" @bind="_hardCaseSold" style="width:auto; flex:none;" /></label>
```
Compare with the already-correct pattern used two sections above on the very same form
(`ConsultationForm.razor:207`, `:228`):
```html
<label><input type="checkbox" @bind="_consentGiven" style="width:auto; margin-right:8px;" />Customer consents to be contacted...</label>
<label><input type="checkbox" @bind="_orderFromDotGlasses" style="width:auto; margin-right:8px;" />Order this lens from Dot Glasses...</label>
```
— checkbox first, label text after, no parenthetical instruction needed because the checkbox is
the obvious, natural focal point.

**Desired behavior:**
Match the two other checkboxes already on this same form: checkbox first (or at minimum clearly
sized/positioned as the primary control, not squeezed to the edge), label text second, and drop
the "(click for yes)" parenthetical — it's only needed today because the control doesn't read as
a checkbox at a glance.

**Key interfaces:**
- `src/DotGlasses.App/Pages/ConsultationForm.razor:239` (the label/checkbox to reorder)
- `src/DotGlasses.App/Pages/ConsultationForm.razor:207`, `:228` (the two already-correct sibling
  checkboxes on the same form — copy their markup pattern exactly rather than inventing a third
  variant)

**Acceptance criteria:**
- [ ] The hard-case checkbox visually matches the consent/order-from-Dot-Glasses checkboxes
      elsewhere on the same form (checkbox-then-label, no parenthetical instruction text).
- [ ] Checking/unchecking it still correctly drives `_hardCaseSold` and the conditional Hard Case
      Colour dropdown below it (`:241-247`) — no functional change, purely markup/layout.

**Out of scope:**
- Any change to `_consentGiven`/`_orderFromDotGlasses` — already correct, included here only as
  the reference pattern.
