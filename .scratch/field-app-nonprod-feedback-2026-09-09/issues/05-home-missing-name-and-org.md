# 05 — Home screen never shows the technician's name or their active org

Status: ready-for-agent
Blocked by: None — can start immediately
Category: bug

Source: Field App non-prod testing, 2026-09-09, Joe — "Field app says 'signed in as field agent'
but doesn't say my name, or which organisation I'm scoped to on the main call to action list."

## Agent Brief

**Category:** bug (hardcoded placeholder text)

**Summary:** `Home.razor:41-42` hardcodes the text "Signed in" / "Field agent" — it's static markup,
not bound to anything about the actual signed-in user.

**Current behavior:**
```html
<div style="font-weight:700;">Signed in</div>
<div style="font-size:13px; color:#666;">Field agent</div>
```
always renders literally, regardless of who is signed in or which org they're scoped to.

**Desired behavior:**
Show the technician's actual name and their active org. Two pieces are needed:

1. **Name**: `LoginResponse` (`src/DotGlasses.Contracts/Auth/LoginResponse.cs`) doesn't currently
   carry the user's display name — only `AccessToken`/`ExpiresAtUtc`. `ApplicationUser` already
   has a `FullName` field (`src/DotGlasses.Infrastructure/Identity/ApplicationUser.cs:27`), used
   today by the Admin Portal's User Directory. Add `FullName` to `LoginResponse`, populate it in
   `AuthController.Login`/`SwitchOrg` from the already-loaded `user`, and persist it in
   `AuthTokenStore` alongside the token (extend the `PersistedToken` record and
   `SetTokenAsync`/`InitializeAsync`, `src/DotGlasses.App/Auth/AuthTokenStore.cs`) so it survives a
   refresh the same way the token already does. Fall back to the username/email if `FullName` is
   null/empty (matches `UserAdminService.cs:51`'s existing fallback pattern for the same field).
2. **Active org**: already available with no backend change — `IUserLocationClient.GetMyOrgsAsync()`
   (already used by `Settings.razor`) returns each assigned org with an `IsActive` flag. Home
   should call it once on load and show the active org's `Name`.

**Key interfaces:**
- `src/DotGlasses.App/Pages/Home.razor:41-42` (the two lines to replace)
- `src/DotGlasses.Contracts/Auth/LoginResponse.cs` (add `FullName`)
- `src/DotGlasses.Web/Controllers/Api/V1/AuthController.cs:64` and `:109` (`Login`/`SwitchOrg` —
  populate the new field from `user.FullName`)
- `src/DotGlasses.App/Auth/AuthTokenStore.cs` (persist `FullName` alongside the token)
- `src/DotGlasses.App/Auth/IUserLocationClient.cs`/`UserLocationClient.cs` (`GetMyOrgsAsync`,
  already exists — reuse, don't duplicate)

**Acceptance criteria:**
- [ ] After logging in, Home shows the technician's actual name (or their username/email if
      `FullName` is unset) instead of "Field agent".
- [ ] Home shows the name of whichever org is currently active (`IsActive == true` from
      `GetMyOrgsAsync`).
- [ ] Switching location (Settings' Active Location) updates what Home shows on next visit.
- [ ] A refresh (persisted-token rehydration path) still shows the correct name — verify
      `AuthTokenStore.InitializeAsync` round-trips the new field correctly.

**Out of scope:**
- Any change to what `Settings.razor`'s own location picker shows — it already works.
- Adding the user's name/org into the JWT claims themselves — going through `LoginResponse` (and
  persisting it client-side the same way the token already is) is simpler and keeps JWT parsing
  out of the client entirely, which it currently doesn't do at all.
