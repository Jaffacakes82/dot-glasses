## Agent Brief

**Category:** bug
**Summary:** Block Field App form submission when compulsory fields are blank

**Current behavior:**
Forms in the Field App consultation flow can apparently be submitted with at least some
compulsory fields left blank, per the reviewer's report.

**Desired behavior:**
Submission is blocked client-side, with immediate inline feedback, whenever a compulsory field
is blank — extending the project's existing client-side pre-submit validation pattern
(`App/Validation`, which already maps server-side rejections back onto fields by DTO property
name) so the same required fields are checked *before* submission is attempted, not only after a
round trip to the server.

**Key interfaces:**
- The Field App's client-side pre-submit validation — extend coverage to every field the
  corresponding request DTO requires, kept in sync with the server-side FluentValidation rules
  for the same DTOs so client and server never disagree about what's required.

**Acceptance criteria:**
- [ ] Attempting to submit a form with any compulsory field blank is blocked client-side with a
      clear inline error, before any network/outbox write is attempted.
- [ ] The set of fields enforced client-side matches what the server actually requires for the
      same request type.
- [ ] Optional fields remain submittable blank.

**Out of scope:**
- Changing which fields are required — this ticket only enforces existing requirements more
  reliably, it doesn't add or remove any.
