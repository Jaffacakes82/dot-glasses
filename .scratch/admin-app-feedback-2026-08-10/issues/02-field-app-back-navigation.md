## Agent Brief

**Category:** enhancement
**Summary:** Add an explicit in-app back navigation control to the Field App's multi-step flows

**Current behavior:**
There is no in-app back control. Navigating backward relies solely on the phone's native back
gesture/button, which isn't available when testing in a desktop browser and may not be
discoverable to technicians in the field.

**Desired behavior:**
Field App screens reached via forward navigation (e.g. consultation form steps) expose a
visible, explicit back control that steps back through the app's own navigation history. The
phone's native back button/gesture continues to work as before, unaffected — this is additive,
not a replacement.

**Key interfaces:**
- Field App page/component navigation — a shared layout element or per-page control invoking the
  app's own back-navigation (not a bare `history.back()`, if that would leave a half-submitted
  form in an inconsistent state).

**Acceptance criteria:**
- [ ] Every multi-step Field App screen exposes a visible back control that returns to the
      previous step/screen.
- [ ] The control works identically in a desktop browser and on a phone.
- [ ] In-progress form data on the screen being left is handled sensibly (preserved on return, or
      an explicit warning if it would be discarded) — no silent data loss.
- [ ] The phone's native back button/gesture continues to work as before.

**Out of scope:**
- Redesigning the Field App's overall navigation/routing structure.
