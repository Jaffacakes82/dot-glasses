**The "purple renders as pink" report is very likely a naming mismatch, not a rendering bug**:
the reporter's own labels for these two images were "Pink" / "Pink Black," while the code and the
image filenames both say "Purple" / "Purple_white". Nothing in the app appears to be misrendering
a colour value — the internal label just doesn't match what the e-commerce site calls it. Given
the reporter used "Pink" when supplying these assets, treat this as a relabel: rename the two
`ReferenceDataItem` rows from "Purple"/"Purple-Black" to "Pink"/"Pink Black" (a Reference Data
admin-screen edit or a seed-data change — not a colour/CSS fix) to match the e-commerce site. No
separate rendering-bug investigation needed.

covers it, no separate dropdown-as-fallback mechanism is needed. Remove the separate "full frame
or eye frame only" dropdown entirely per the reviewer's explicit ask, since it's a distinct,
confusing element rather than something tied to icon coverage gaps.
