**Summary:** Replace generic "child node" language on the Organisations screen with

The Organisations screen's add-child action is labeled using generic "child node" language,
regardless of what level/kind of organisation is actually being added.

The label reflects the organisation level/kind being added — e.g. "Add country office," "Add
retail point," "Add retailer/distributor" — derived from `OrganisationLevel` (and the free-text
`Kind` for Intermediate nodes) rather than the generic word "node."

**Key interfaces:**
- The Organisations screen's add-child UI copy — driven by the target level (and `Kind`, where
  applicable) being added.

**Acceptance criteria:**
- [ ] The add-child action's label names the specific organisation type being added, instead of
      the generic word "node."
- [ ] The label is correct at every level the tree shape allows a child to be added (DGI→Country,
      Country/Intermediate→Intermediate or RetailPoint).

**Out of scope:**
- Any change to add-child behavior or the tree-shape rules themselves — copy only.
